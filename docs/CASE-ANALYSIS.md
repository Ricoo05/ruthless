# Case-linked AI analysis — v0.13

Open **Case analysis** in the assessment desk (or `/#analysis`). Select a fictional intelligence question and inspect its selected reports. Choose Domestic, Cross-border or International context, then **Create case with selected reports**. This atomically retains the question and every original excerpt in a new Draft assessment. It adds no evidence or judgment.

**Load saved AI draft (no API cost)** attaches the corresponding retained output from the earlier synthetic OpenAI experiment. The two bundled candidate files in `dist/examples/` contain the six development and six visible reserved outputs from gpt-5.4-mini-2026-03-17 / ai-attribution-v2. They contain no credentials, provider raw output or customer documents. Citation checks are recomputed on attachment. These outputs remain semantically unreviewed; an editable candidate label does not authenticate provider provenance. **Try authored example** instead uses a clearly labeled deterministic authored control without calling AI.

For another saved output, paste a `ruthless-evaluation-candidates` version 1 file under **Attach an existing synthetic AI draft**. The selected scenario must have an output with valid exact citations (or an explained abstention), and its complete source set must match current retained case documents. Wrong questions/splits, missing outputs, altered quotes, ambiguous/missing source bindings and superseded documents reject without changing the workspace. Imported semantic annotations or approval claims are not carried into the case inbox.

On an explicitly configured loopback server, **Generate draft for this case** requests one approved model call. The existing service receives only the bundled scenario ID, split and acknowledgement; it resolves authored inputs server-side. User-entered reports are never sent to a provider through this route. The configured model, bounded output tokens and existing session request allowance still apply; restarting a server resets its attempt allowance and does not establish a monetary budget. Hosted static previews cannot execute model requests. The previous local session currently has zero attempts remaining; no new paid call was needed for this release. The new in-desk request path shares the tested service, but has not been exercised against a paid provider in browser QA.

Drafts retain the assessment snapshot, every selected original report, citation-to-workspace-document bindings, creation date and candidate output. The workspace may contain other reports; only the visibly selected bundled reports are part of the model input. **Open assessment** returns to the same case. **Inspect cited drafts** returns from that case to its inbox. Review this source for evidence opens the manual intake review directly from the selected report. Incorporation still requires an attributed statement, source-conditions acknowledgement and review note; attaching a draft never incorporates evidence.

An analyst may record **Considered** or **Rejected** with a note. Considered records that note; it does not establish semantic quality, approve evidence, change the assessment or replace the per-criterion semantic-review screen. Changes to the assessment or selected source content, and newly staged corrections superseding a selected source, make earlier drafts stale. Stale drafts remain visible and exportable as history, but cannot be marked Considered. Rejection remains available. Intake review notes alone do not alter an otherwise unchanged source snapshot.

Workspace format v7 retains the v6 `analysisRuns`, bounded to 40 drafts. Each output retains the existing eight-proposal/four-citation bounds; the complete workspace still has a 2 MB UTF-8 limit. Versions 1–5 upgrade with an empty analysis inbox. Versions 1–6 receive no invented judgment lineage; v6 analytical drafts are preserved. The save/open validator checks source bindings and output spans on restoration. Assessment briefs now include a clearly separated analytical-draft section with stale status, source citations and consideration notes. Imported workspace files and history remain editable, unencrypted and unauthenticated.

Unapplied JSON/analysis notes block navigation and save/export until attached, recorded or explicitly cleared; an in-flight validation/request blocks workspace replacement. A result received after an unexpected workspace change is retained in the JSON field for manual attachment. There is no automatic persistence. Save workspace requests a file download, whose actual receipt remains unverified in the current browser.


## From considered draft to analyst judgment

Every cited report must first be incorporated manually into evidence for the same case. A current Considered draft then offers **Prepare assessment from this draft** for each attributed proposal. Abstentions, rejected/pending drafts and stale inputs cannot be prepared. The preview retains the proposal text and limitations and maps exact source citations to the corresponding evidence IDs. It neither mutates the workspace nor writes new evidence.

**Use as unapplied assessment** fills an editable judgment form, selecting those evidence records, starting at Needs review / Insufficient confidence and clearing the review note. If the case already has judgment, gaps or citations, explicit replacement acknowledgement is required. Edit and **Apply assessment** manually; **Discard unapplied changes** restores the last applied case. The source snapshot is checked again at application to reject a stale preview. Existing requirements for Reviewed judgments and challenging evidence remain in force.

The applied case and brief record originating run/proposal IDs, preparation date and source evidence IDs. Status-only updates preserve this historical starting point; later judgment/gap/citation changes outside preparation clear it. Analyst edits during preparation are allowed, so lineage does not claim verbatim text or semantic approval. Application makes the earlier draft's assessment snapshot stale while retaining the draft as history.

## Whole-workspace recovery

**Preview workspace JSON** shows the complete applied session as read-only JSON. Manually retain the text and use **Paste workspace JSON** to restore it in a fresh session. Validation rejects malformed, unsupported, oversized or invalid-linked records before replacing anything. Replacing unsaved current work requires explicit acknowledgement. Successful restoration clears transient analysis inputs and filters. Unapplied edits and active requests block replacement.

The authored browser control recovered the complete case, reports, evidence, considered draft and applied lineage exactly. This verifies pasted-JSON recovery only: native file-download receipt and downloaded-file reopening remain unverified. There is no autosave, encryption, authenticated identity or protected audit integrity.
