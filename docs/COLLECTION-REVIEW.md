# Source collection review — v0.16

The local collector and browser review now form a working source-to-intake path. Run `node scripts/collect-advisory.mjs --collect`, open Source collection, and paste the resulting report JSON. The hosted private UI can inspect pasted reports but does not run the collector. No file-upload mechanism or cross-origin exception was added.

Loading validates the source, fixed URLs, timestamps, required sections, bounded schema and selected-content SHA-256. Failed reports carry no passages. The screen shows the latest loaded attempt and last successful report separately; a failure does not hide an older retained capture. A capture becomes stale after 24 hours. Reports older than the latest loaded attempt reject without replacing the existing context. The UI knows only reports loaded in this session, not every collection attempt performed elsewhere.

HTML is parsed in an inert template whose nodes are never attached to the page. Scripts, styles, templates, embedded documents, SVG/math, hidden and aria-hidden content are excluded. Text leaves the parser as a string; page rendering escapes it. Block boundaries and whitespace are normalized using `html-text-v1`. Embedded links do not become actionable links. This is plain-text extraction, not a complete simulation of publisher CSS or browser-visible layout; source text and parser version remain distinct from raw HTML. The original HTML stays in the local collector report, outside the static Site.

Choose an assessment explicitly, copy a unique exact passage of 1–4,000 characters from the displayed section, record the source-access review, and acknowledge the conditions. Staging uses the existing atomic source-batch contract. It retains the passage, publisher, section URL, UTC publisher/observation dates, parser version, text offsets, capture ID, selected-content hash and analyst rights review. These are local unverified records, not signed publisher authentication. A rights acknowledgement cannot create permission that does not exist.

All sections use one FCDO reporting group. An unchanged passage skips without adding a document or batch-history record, and preserves its original capture date and rights notes. A new passage has a stable identifier bound to its assessment, publisher content ID, section, title, publication date, extraction version and excerpt. A changed passage can explicitly supersede a current excerpt from the same section and assessment, with a correction explanation; older records remain intact and normal review reopening applies. The app does not automatically decide that a new passage corrects an earlier one.

Unfinished pasted JSON and passage selections block navigation, saving or replacement until validated/cleared or staged/discarded. Changing the source section while a passage is edited is blocked. Loading a report and staging a passage create no evidence, judgment or approval. Document intake retains its separate incorporation review, and Indicator triage can inspect staged text using literal queries.

The current local backend and AI runner remain synthetic-only. Real-source workspaces cannot be saved to that backend and cannot become bundled AI inputs. Use the existing workspace JSON preview/pasted recovery or verified file receipt to retain staged material. Loaded collection reports, freshness context and unapplied selections are session-only; workspace JSON contains staged passages and their lineage, not the full captured HTML or coverage ledger. No paid API request or hosted ingestion worker is added.

Source access decisions, coverage limits, licensing references and future worker requirements remain in `COLLECTION-ARCHITECTURE.md`. The next useful slice is a controlled local bridge for collector reports and a broader permitted institutional-source inventory; unattended collection still requires rate/retention/storage limits. No internet-wide recall, attack-prediction accuracy or prevention-effectiveness claim has been measured.
