# Indicator triage and fictional regional exercise

Implemented 5 October 2026, v0.15. This is an analyst query workflow over retained workspace records. It does not fetch the internet, monitor social platforms or evaluate a model.

Open Indicator triage. Define one to eight comma-separated literal terms of up to 80 characters, any/every-term matching within one record, publication start date, known-by date, geographic scope and a recorded source-group threshold (1–10). Run the query explicitly. Applied settings are displayed with results, so editing the form does not silently relabel an earlier query. Invalid settings preserve current workspace data.

The scanner uses original retained excerpts where available and direct analyst evidence statements otherwise. It does not count an incorporated document again through its paraphrase. Staged excerpts remain visibly unincorporated. Publication and recorded dates must fall within the knowledge boundary. Corrections known by that date replace earlier source text; a future correction does not suppress a report in an earlier query. This filters retained source rows; it does not reconstruct the full historical workspace, case assignments or labels as they existed on that date.

Matches retain source IDs, publisher, original text, URL where recorded, locator, permission notes, claim/relation labels, dates and exact UTF-16 span positions. Case counts collapse case-insensitive recorded source-group labels. Those labels do not establish independent corroboration. Shared groups across cases identify shared reporting metadata, not a common actor, incident or causal link.

The display shows the first 50 matching records and the first 20 occurrences per term in each record, with total counts and visible truncation labels. Narrow a query to inspect further results. Unicode passages, literal regular-expression characters, negations, unknown claims and no-result cases have tests. A matching phrase can describe a denied allegation or ordinary activity. Thresholds prioritize analyst review only; they are not probabilities or validated threat labels. Different wording, missing data, delayed reports and limited source coverage can miss relevant material.

Load fictional regional exercise requires explicit acknowledgement. It appends two fictional cases and four source excerpts atomically, preserves existing records, and rejects repeated insertion. Training Sector R-7 and Region X-4 are invented areas; all publishers and events are authored controls. The scenario retains an unverified warning, same-source repost, benign alternative and overseas repost. Query `threat`, known by 2026-10-05 or later. Four records match across two cases; the regional case has three records from two recorded groups. The negated benign account deliberately matches. This demonstrates a review workflow and a false-alarm example, not measured threat-detection accuracy.

Prepare verification task prepopulates the existing task form with the case, query/date and a bounded set of source IDs, asking for original context, alternative explanations and source independence. The analyst reviews scope, owner and due date, then explicitly creates the task. It executes no operation, collects no new source and inserts no evidence. Intake incorporation, case judgments, AI drafts and task completion continue through their existing separate checks.

Queries and derived results are session-only and recomputed on revisiting the view. They are not authoritative stored alerts. Added fictional cases, sources and explicitly created tasks use the normal workspace save/recovery format (version 7). Retain the workspace before closing. No new paid request, native file-import attempt or checkpoint archive was created.

An agency demonstration should identify exactly which functions run, which records are fictional, and which conclusions remain unverified. Prevention and detection-performance claims need authorized practitioner evaluation, unseen representative examples, missed-threat/false-alarm measures, source coverage and a human response process. [NIST's AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) provides testing and evaluation guidance for future AI components. It does not certify Ruthless or prescribe this particular rule set.

Broad internet and social-source integration is the next design priority. Approved sources, supported APIs and authorized exports must preserve attribution, original timestamps, corrections, duplicate lineage, collection failures and retention constraints. No live collector is implemented in v0.15.
